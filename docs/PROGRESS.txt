ПРОГРЕС НА ПРОЕКТА (Екип 4)
===========================

1. Какво е направено
- 3-слойна архитектура: MySQL (Docker), backend (Node.js/Express), frontend (Vanilla JS).
- 496 игри от IGDB: еднократно теглене, чистене, зареждане (fetch, clean, seed).
- Полета: описание, жанрове, платформи, кадри, PEGI възраст и официален текст.
- 249 обяснения на български (превод на PEGI дескриптори, ръчно прегледани).
- REST API: търсене, филтри (студио, рейтинг, PEGI, жанр), сортиране, страниране.
- Пълен CRUD за игри, валидация на входа (validate.js).
- Профили (bcrypt, JWT), харесвания, trending, препоръки, изход с анулиране на токен.
- Сигурност: ограничение на опитите за вход, CORS и тайни в .env.
- Рефакторинг (withDb), node:test, CI през GitHub Actions, test_all.sh (36/36).

2. Как се стартира
- docker compose up -d (изчакай ~20 секунди)
- cd backend && npm install && node scripts/seed.js && node scripts/explain_bot.js --apply
- node --env-file=.env server.js
- npx serve frontend
- Adminer: порт 8080

3. Срещнати трудности и решения
- Липсващ Docker Compose plugin: ръчно инсталиране на binary от GitHub.
- Mojibake: SET NAMES utf8mb4 в init.sql и charset в Node връзката.
- Счупени снимки (Wikipedia hotlink): преминахме към IGDB изображения.
- Connection lost при seed: MySQL иска ~20 секунди след старта.
- node_modules беше в Git: махнат с git rm --cached.
- Gemini: смяна на модел (404), дневен лимит (429) и счупен JSON от кавички;
  решение: порции, само id и text, ръчен преглед.
- Bash и "!" в двойни кавички: скриптовете се пишат във файл.

4. Известни ограничения
- Анулираните токени са в паметта (чистят се при рестарт).
- PUT/DELETE за игри са достъпни за всеки влязъл потребител (няма роли).
- Няма хардуерна проверка "ще ми тръгне ли играта".
